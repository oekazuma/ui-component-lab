## Findings considered and rejected

- Splitting the detail-page bundle (eager glob loads all 45 demos, 57 kB gzip): not worth it yet. Client-side navigation caches it, and the home page needs every demo anyway. Revisit when the component count roughly doubles, and move data to `+page.server.ts` then.
- Shared roving-tabindex helper: only 2 demos share the lookup-object handler (tabs, toolbar), and each demo should read standalone.
- textarea counter counts UTF-16 code units: consistent with `maxlength` in text-field, and "characters" is ambiguous. Not a bug.
- `data-sveltekit-reload` on the language link: fixes 002 in one attribute, but a full reload wipes the home page's search and filter state.
- file-upload alias URL (`/file-upload/`) vs source URL (`/file-upload/usage/`): intentional. The alias links the overview, and the source links the page the text came from.
- Category changes (tabs → disclosure, divider/avatar/badge under `data`): a judgment call for the maintainer, low confidence.
- `prepare` script `|| echo ''`: stock SvelteKit template; `pnpm check` surfaces sync failures.
- Removing top-level `permissions: pages: read`: `actions/configure-pages` uses it.
- Compare view from `related`, dark mode, staleness badge from `checkedAt`, Fuse.js, filters in the URL, ESLint, vitest, meta CSP: either already covered, ceiling not hit (see the `ponytail:` comments), or no grounding in the repo.
